
# 港美股量化交易通知系统需求文档

## 一、项目目标

* 通过 **iTick 提供的美股实时行情** + **Backtrader 回测/策略引擎**
* 系统不直接下单，仅生成交易信号并通过 **飞书机器人** 或 **微信消息**推送通知
* 用户根据通知在 **富途牛牛或其他券商客户端** 手动下单

---

## 二、系统架构

```
[iTick 行情 API]  →  [数据预处理模块] → [Backtrader 策略引擎] → [信号生成模块] → [飞书/微信通知] → [用户手动下单]
                                 ↑
                          [用户自定义股票池]
```

---

## 三、功能需求

### 1. 股票池管理

* 用户可自定义交易股票列表：

  * 手动输入股票代码（如 `AAPL, MSFT, TSLA`）
  * 上传 CSV 文件
* 系统对输入股票做有效性校验：

  * 是否在 iTick 支持的市场
  * 去重、规范化（大写、去空格）
* 策略仅对用户指定股票池执行

---

### 2. 数据模块

* 接入 iTick 实时行情 API（WebSocket / HTTP）
* 支持以下行情类型：

  * 分时、分钟、日 K 线
  * 成交量、买卖盘深度（可选）
* 支持历史行情存储（CSV / SQLite / Parquet）用于回测
* 支持回放历史行情进行策略验证

---

### 3. 策略模块

* 集成 Backtrader 支持策略回测与实时执行
* 系统内置常用量化策略模板：

  * **均线交叉**（短期均线 vs 长期均线）
  * **RSI 超买超卖**
  * **布林带回归**
  * **突破策略**
  * **动量因子策略**
* 每个策略必须定义 **买入 / 卖出信号触发条件**
* 信号输出字段示例：

```json
{
  "symbol": "AAPL",
  "time": "2025-08-31 10:30:00",
  "action": "BUY",      // BUY 或 SELL
  "price": 189.23,
  "stop_loss": 185.0,
  "take_profit": 195.0,
  "strategy": "MA_Crossover"
}
```

---

### 4. 信号推送模块

* **飞书机器人**：

  * 配置 Webhook URL
  * 支持卡片消息或文本消息
* **微信消息**：

  * 企业微信机器人 Webhook 或 Server 酱
* 推送内容包含：

  * 股票代码/名称
  * 时间
  * 买入/卖出动作
  * 建议价格、止损止盈
  * 策略来源
* 支持推送频率控制（如 1 分钟汇总或单条推送）

---

### 5. 手动下单

* 用户根据通知，在券商客户端手动执行交易
* 系统不直接下单，保证合规和安全

---

### 6. 配置管理

* 配置文件（YAML/JSON）管理：

```yaml
stock_pool:
  - AAPL
  - MSFT
  - TSLA

strategy:
  type: MA_Crossover
  short_window: 10
  long_window: 50

notification:
  enabled: true
  method:
    - feishu
    - wechat
```

* 支持策略参数调整、股票池修改、通知方式开关

---

### 7. 日志与监控

* 系统记录：

  * 策略信号生成日志
  * 推送状态（成功/失败）
  * 错误和异常
* 推送失败自动重试

---

## 四、非功能需求

* **开发语言**：Python 3.9+
* **运行环境**：本地 PC / Mac / Linux
* **实时性**：行情延迟 < 1s（依赖 iTick）
* **可扩展性**：

  * 未来可接入 API 自动下单（IB / Futu OpenD 等）
  * 可增加更多策略模板

---

## 五、准备工作

1. 注册 iTick 并获取 API Key
2. 本地搭建 Python 环境，安装 Backtrader、pandas、websocket-client 等
3. 准备推送服务：

   * 飞书机器人 Webhook
   * 微信机器人（企业微信 / Server 酱）
4. 准备策略逻辑（均线、RSI、布林带等）
5. 本地测试流程：

   * 历史数据回测 → 实盘行情运行 → 推送通知
   * 用户收到通知 → 手动下单
